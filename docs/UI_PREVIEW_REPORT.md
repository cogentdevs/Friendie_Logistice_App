# UI preview through Sign In

For the user's current UI-only workflow, debug builds default UI_PREVIEW_ENABLED to true. Tapping Sign In with empty or arbitrary fields opens the existing Home/Drawer/Tabs without form validation, an API call, a token or an authenticated user. Login displays an explicit UI preview note; Home/Drawer show development preview identity. The state lives only in memory and resets on restart. Drawer offers Exit UI preview.

This uses a separate development Zustand store and the existing root route gate. It never sets authStore to authenticated and never writes Keychain/AsyncStorage credentials. Bootstrap skips real session restoration during debug UI preview so an absent/unconfigured backend cannot block the UI workflow. Secure credentials, if present, are not deleted. Release builds are guarded by __DEV__ and retain actual authentication. Set UI_PREVIEW_ENABLED=false in .env and run npm run configure:env to test real login validation/API behavior again. Legacy NAVIGATION_PREVIEW remains separate and normally false.
